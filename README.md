# pii-mask-enhanced

Данная версия проекта представляет собой модификацию (форк) задокументированного ниже `pii-mask`. Версия `enhanced` включает в себя независимые от основного проекта обновления, которые направлены на улучшение функционала, исправление ошибок и рефакторинг. Все права на оригинальный код принадлежат [@dewil](https://github.com/dewil) согласно лицензии MIT. `pii-mask-enhanced` распространяется по той же лицензии.

`pii-mask-enhanced` - библиотека маскировки персональных данных перед отправкой текста в облачные LLM и обратной подстановки оригиналов в ответ. Она подключается как зависимость к другому проекту и дополнительно дает консольную команду `pii-mask`. Библиотека русскоцентричная и включает в себя ПД-форматы РФ, NER и морфологию русского языка.

**PII** (personally identifiable information) - принятое в отрасли обозначение персональных данных. Название `pii-mask` происходит от этого термина.

```
"Иван Петров, тел 8 903 123-45-67, оформи заявку"
        │ mask
"{{PERSON_1}}, тел +7 000 000-00-01, оформи заявку"   →  в облачную LLM
        │ ответ модели
"Заявка для {{PERSON_1}} создана, звонок на +7 000 000-00-01 назначен"
        │ unmask
"Заявка для Иван Петров создана, звонок на 8 903 123-45-67 назначен"
```

Облачная модель никогда не видит настоящих данных. Основной сценарий - обработка транскриптов встреч и документов (саммари, action items) без утечки имен, телефонов и компаний провайдеру модели.

## Устройство

Персональные данные ищутся на трех уровнях, от дешевого к дорогому:

1. **Regex + контрольные суммы** (форматные ПД РФ): телефон, email, ИНН (10/12, контрольные цифры), ОГРН и ОГРНИП (13/15, контрольный разряд), СНИЛС, карта (Луна), паспорт (только рядом со словом "паспорт"/"серия"), telegram-ник, УИД договора (758-П), а также ФИО в тех формах, которые NER не берет: капсом и с инициалами (см. ниже).
2. **NER** ([Natasha](https://github.com/natasha/natasha)/slovnet, CPU, офлайн): имена и организации. Ключ консистентности - нормальная форма: "Иван Петров", "Ивана Петрова" и "Иваном Петровым" дают одну метку. Одиночное имя ("Иван", "Петров") линкуется к единственному подходящему полному ФИО.
3. **LLM-аудитор** (опционально; готовая реализация через Ollama, можно подключить свою модель): второй проход по уже замаскированному тексту. Ловит косвенные идентификаторы: "моя жена Оля", адреса без формата, ники. Модель только предлагает кандидатов (литеральные подстроки), конечную замену производит код.

Принципы:

- **LLM не переписывает текст.** Все замены детерминированные: код заменяет только найденные участки текста (спаны), остальной текст не меняется.
- **Stateless.** Mapping "метка -> оригинал" возвращается вызывающему. Библиотека ничего не хранит.
- **Fail-closed.** Если шаг маскировки не выполнился или в файле есть текст, который библиотека не умеет обезличить, то выдаётся ошибка.
- **Формат-сохраняющие фейки** для телефонов (`+7 000 ...` - несуществующий код) и email (`userN@example.com`): модель обращается с ними естественно. При обратной подстановке телефоны матчатся и по цифрам.
- **Защита от выдумок.** Метка или фейк, которых не было во входе, при unmask превращается в `[неизвестное значение]`.
- **Пропуск дороже лишней маски**: golden-тесты проверяют recall ("ни одна строка из списка не дожила до masked"). Ложные срабатывания в golden-тестах не считаются ошибкой.

Название города или страны (`LOC`) по умолчанию не маскируется: фраза «Москва - столица» не будет считаться за персональные данные. Место маскируется как адрес, если перед ним стоит подпись («место рождения:», «страна:»), слово-признак («г.», «в городе», «пгт») или регион («Тверская область», «Республика Татарстан»). Чтобы скрывать названия, не стоящие рядом с регулярками, тип `LOC` добавляют к списку типов (`--types` заменяет список целиком, поэтому в нем перечисляют и остальные нужные типы). Даты скрываются только рядом с ПД (дата рождения, дата выдачи документа). Суммы денег не маскируются, кроме дохода, остатка по счету и долга человека.

## Установка

Требуется наличие Python версии 3.11+.

**Как зависимость проекта** (версия фиксируется тегом):

```bash
pip install "pii-mask-enhanced @ git+https://github.com/SuperB1aze/pii-mask-enhanced.git@v1.0.0"
```

Дополнительные наборы (`pii-mask-enhanced[audit,word]`):

- `[audit]` - аудитор на [Ollama](https://ollama.com) (`httpx`); сама Ollama с моделью ставится отдельно.
- `[word]` - конвертация `.doc`, `.xls` и `.ppt` (Office 97-2003) через MS Word, Excel или PowerPoint на Windows (`pywin32`). Вместо них подходит LibreOffice.

Для `.pdf` нужен `pdftotext` (poppler-utils).

**Для разработки:**

```bash
git clone https://github.com/SuperB1aze/pii-mask-enhanced.git
cd pii-mask-enhanced
python -m venv venv
venv\Scripts\Activate.ps1        # Windows (PowerShell); Linux: source venv/bin/activate
pip install -e ".[dev]"
```

## Пример использования в коде

```python
from pii_mask_enhanced.engine.settings import Options, build_masker
from pii_mask_enhanced.formats import word

masker, _ = build_masker(Options(preset="auto"), lambda: text)
masked, mapping = masker.mask(text)
restored = masker.unmask(answer, mapping)

mapping = word.mask_document("договор.docx", "договор.masked.docx", masker, mapping)

# с аудитором
from pii_mask_enhanced.audit import OllamaAuditor

masker, _ = build_masker(Options(), lambda: text, OllamaAuditor(url="http://10.0.0.5:11434"))
masked, mapping = masker.mask_with_audit(text)
```

`Options` принимает те же настройки, что флаги CLI. Остальные форматы - в `formats.excel`, `formats.powerpoint` и `formats.pdf`. Если файл обезличить не удается, библиотека выбросит исключение.

Свой аудитор - любой объект с методами `available() -> bool` и `find(masked_text)`, который возвращает пары «подстрока, тип» (тип из реестра библиотеки, например `PERSONAL`). Подстроки ищутся в тексте буквально и проходят те же фильтры, метки ставит библиотека. Готовые промпт и нарезка текста - `audit.PROMPT` и `audit.chunks`.

Библиотека не читает переменные окружения: настройки передаются параметрами. `OllamaAuditor.from_config(path)` берет их из секции `[audit]` файла настроек (см. ниже).

## CLI

**Пайплайн транскрипта:**

```bash
pii-mask mask встреча.md                  # -> встреча.masked.md + встреча.mapping.json
# встреча.masked.md уходит в облачную LLM, ответ сохраняем в summary.md
pii-mask unmask summary.md --mapping встреча.mapping.json -o summary.final.md
```

**Форматы на входе:**

| Вход | Результат |
|---|---|
| текст (`.md`, `.txt`, `.csv`, `.log` и т.п.) | `.masked` + то же расширение (`клиенты.csv` -> `клиенты.masked.csv`); без расширения - `.masked.md`, для `-` (stdin) - stdout |
| `.docx` | `.masked.docx` - оформление сохраняется; текст, колонтитулы, примечания, диаграммы (вместе с книгой их данных), SmartArt, замещающий текст картинок |
| `.doc` | `.masked.doc` - через временную конвертацию в `.docx` и обратно; `-o файл.docx` оставляет `.docx` |
| `.xlsx` | `.masked.xlsx` - ячейки, примечания, колонтитулы, надписи и фигуры, диаграммы, SmartArt, кэш сводных таблиц; имя листа с ПД маскируется вместе со ссылками на лист в формулах |
| `.xls` | `.masked.xls` - через временную конвертацию в `.xlsx` и обратно; макросы VBA не сохраняются; `-o файл.xlsx` оставляет `.xlsx` |
| `.pptx` | `.masked.pptx` - слайды, заметки, комментарии, диаграммы (вместе с книгой их данных), SmartArt |
| `.ppt` | `.masked.ppt` - через временную конвертацию в `.pptx` и обратно; `-o файл.pptx` оставляет `.pptx` |
| `.pdf` | `.masked.md` - только текст; сканы без текстового слоя не поддерживаются |

`unmask` принимает текст, `.doc`, `.docx`, `.xls`, `.xlsx`, `.ppt` и `.pptx`. Документ, книга и презентация восстанавливаются в файл того же формата. Ячейка Excel, которая до маскировки была числом, снова становится числом.

Повторный `mask` следующего куска диалога с тем же `--mapping` продолжает нумерацию: одна сущность - одна метка на весь диалог.

**Флаги:** `--audit` (LLM-аудитор), `--no-ner` (только форматные), `--types PERSON,PHONE,...`, `--org-dict файл` (названия организаций списком), `--config файл` (файл настроек). Полный список - `pii-mask mask --help`.

**Файл настроек** `pii-mask.toml` ищется в текущем каталоге, затем в пользовательском конфиге (`%APPDATA%\pii-mask\config.toml` на Windows, `~/.config/pii-mask/config.toml` на Linux/macOS); путь можно указать явно через `--config`.

```toml
[audit]
url = "http://127.0.0.1:11434"   # по умолчанию
model = "qwen3.5:4b"             # по умолчанию
timeout = 600
keep_alive = "60s"

[convert]
soffice = "C:/Program Files/LibreOffice/program/soffice.exe"
```

Переменные окружения важнее файла: `PII_MASK_OLLAMA_URL`, `PII_MASK_AUDITOR_MODEL`, `PII_MASK_KEEP_ALIVE`, `PII_MASK_SOFFICE`.

**Именованные наборы.** Что считать персональными данными, описано в самой библиотеке в виде наборов: вызывающему достаточно выбрать набор по имени или доверить выбор `auto`.

```bash
pii-mask presets                              # какие наборы есть и что в них
pii-mask mask резюме.pdf --preset resume      # мягко к организациям: работодатели без ООО
pii-mask mask счет.xlsx --preset accounting   # строго: торговые марки остаются в номенклатуре
pii-mask mask файл.md --preset auto           # выбрать по профилю документа
```

Список типов у наборов общий, различаются они строгостью к организациям (`accounting` требует правовую форму), должностями (`resume`) и остатками по счетам и долгами (`accounting`). Флаг поверх набора может только добавить строгость (`--preset resume --ner-org-needs-form`). Чтобы ослабить ее, нужно выбрать другой набор. `--types` поверх набора заменяет список типов целиком.

**Mapping-файлы.** `*.mapping.json` содержит оригиналы ПД. На Linux/macOS CLI ставит ему права 600 (только владелец); на Windows это не работает. Паттерн внесен в `.gitignore` вместе с результатами `*.masked.*` и `*.unmasked.*`. Файл живет рядом с задачей и удаляется вместе с ней.

## Тесты

Тесты проверяют, что библиотека не пропускает ПД и, одновременно с этим, не ломает никакой логики:

- **распознаватели** - форматы и контрольные суммы (ИНН, СНИЛС, карта и т.д.), отсечение похожих номеров вроде артикулов;
- **маскировка и обратная подстановка** - одна сущность получает одну метку, mask -> unmask возвращает оригинал, повторный mask не создает второго слоя меток;
- **golden-тесты** (`tests/golden/`) - на вымышленных транскрипте, резюме, договоре, кадровом приказе и логе ни одна строка с ПД и ни одна ее значимая часть (фамилия, домен, цифры номера) не должны дожить до замаскированного текста. Файлы, сделанные настоящими Word, Excel и PowerPoint (`tests/golden/office/`, пересборка - `build.py`), проверяются по всем частям архива, включая вложенные книги диаграмм;
- **форматы файлов** - .docx, .xlsx, .pptx, .pdf, .doc, .xls, .ppt: текст меняется, структура документа остается;
- **наборы и CLI**.

```bash
python -m pytest -q        # в активированном venv с dev-зависимостями
```

Часть тестов пропускается, если в системе нет нужной программы: PDF - без `pdftotext` (poppler-utils), конвертация .doc через Word - без MS Word и `pywin32`. Реальные ПД в тестах не используются.

## Официальные документы: акты, реестры, выгрузки

- **Извлечение текста из табличного PDF.** `extract_text` извлекает текст с флагом `-layout`, сохраняя колонки. В табличном PDF колоночный режим разносит ФИО, УИД и пары "реквизит - значение" по разным строкам, и часть сущностей теряется. Для таких документов текст лучше извлечь вручную без `-layout` и маскировать полученный файл: `pdftotext акт.pdf акт.txt`, затем `pii-mask mask акт.txt`.
- **ФИО прописными** (`ИВАНОВ ИВАН ИВАНОВИЧ`) ловятся правилами по суффиксу отчества без использования NER (по этой причине маскирование ФИО работает в том числе с `--no-ner`). Одинокое отчество маскируется также.
- **ОГРН и УИД** маскируются по умолчанию, включая УИД, разорванный по дефису.

## Ограничения

- Вместо псевдонимов используются метки: в восстановленном тексте имя всегда стоит в именительном падеже ("заявка для Иван Петров").
- NER может пропускать экзотические имена и транскрипционные искажения - для чувствительных текстов включайте аудитор.
- **Названия организаций маскируются не все.** Название с организационно-правовой формой (`ООО "Ромашка"`, `Ромашка, ООО`) берется правилом. В остальных случаях используется NER, который может терять название рядом с датами и в колоночной верстке резюме. Название без единого формального признака (`Ромашка Россия`) правилами не берется. Такие случаи закрываются списком организаций (`org_names`, `--org-dict`) или аудитором.
- Вложенные объекты в документах Office (вставленный документ, объект OLE) не обезличиваются. Книга с данными диаграммы обезличивается.
- Из документов Office убираются следы автора (кто сохранил и правил, путь сохранения) и миниатюра первой страницы или слайда: это картинка с исходным текстом.
- Агентные сценарии, где модель сама читает файлы, библиотека не покрывает.
- Номера поручений, реестров и входящих не маскируются. Их можно замаскировать отдельным набором правил под конкретный класс документов.
