# pii-mask-enhanced

Данная версия программы представляет собой модификацию (форк) задокументированного ниже `pii-mask`. Версия `enhanced` включает в себя независимые от основного проекта обновления, которые направлены на улучшение функционала, исправление ошибок и рефакторинг оригинального кода. Все права на оригинальную программу принадлежат [@dewil](https://github.com/dewil) согласно лицензии MIT. `pii-mask-enhanced` распространяется по той же лицензии.

`pii-mask` представляет из себя локальный шлюз маскировки персональных данных перед отправкой текста в облачные LLM - и обратная подстановка оригиналов в ответ. Он является русскоцентричным: ПД-форматы РФ, NER и морфология русского языка.

**PII** (personally identifiable information) - принятое в отрасли обозначение персональных данных: всего, по чему человека можно опознать - имя, телефон, email, паспорт, ИНН. Название `pii-mask` происходит от этого термина.

```
"Иван Петров, тел 8 903 123-45-67, оформи заявку"
        │ pii-mask mask
"{{PERSON_1}}, тел +7 000 000-00-01, оформи заявку"   →  в облачную LLM
        │ ответ модели
"Заявка для {{PERSON_1}} создана, звонок на +7 000 000-00-01 назначен"
        │ pii-mask unmask
"Заявка для Иван Петров создана, звонок на 8 903 123-45-67 назначен"
```

Облачная модель никогда не видит настоящих данных. Основной сценарий - обработка транскриптов встреч (саммари, action items) без утечки имен, телефонов и компаний провайдеру модели.

## Устройство программы

Персональные данные ищутся на трех уровнях, от дешевого к дорогому:

1. **Regex + контрольные суммы** (форматные ПД РФ): телефон, email, ИНН (10/12, контрольные цифры), ОГРН и ОГРНИП (13/15, контрольный разряд), СНИЛС, карта (Луна), паспорт (только рядом со словом "паспорт"/"серия"), telegram-ник, УИД договора (758-П), а также ФИО в тех формах, которые NER не берет: капсом и с инициалами (см. ниже).
2. **NER** ([Natasha](https://github.com/natasha/natasha)/slovnet, CPU, офлайн): имена и организации. Ключ консистентности - нормальная форма: "Иван Петров", "Ивана Петрова" и "Иваном Петровым" дают одну метку. Одиночное имя ("Иван", "Петров") линкуется к единственному подходящему полному ФИО.
3. **LLM-аудитор** (опционально, `--audit`, Ollama): второй проход по уже замаскированному тексту - "какие ПД остались?". Ловит косвенное: "моя жена Оля", адреса без формата, ники. Модель только предлагает кандидатов (литеральные подстроки), конечную замену производит код.

Принципы:

- **LLM не переписывает текст.** Все замены детерминированные: код заменяет только найденные участки текста (спаны), остальной текст не меняется.
- **Stateless.** Mapping "метка -> оригинал" возвращается вызывающему (файл рядом с задачей или поле ответа API). Сервис ничего не хранит.
- **Fail-closed.** Если шаг маскировки не выполнился, то текст не уходит дальше.
- **Формат-сохраняющие фейки** для телефонов (`+7 000 ...` - несуществующий код) и email (`userN@example.com`): модель обращается с ними естественно. При обратной подстановке телефоны матчатся и по цифрам.
- **Защита от выдумок.** Метка или фейк, которых не было во входе, при unmask превращается в `[неизвестное значение]`.
- **Пропуск дороже лишней маски**: golden-тесты проверяют recall ("ни одна строка из списка не дожила до masked"). Ложные срабатывания в golden-тестах не считаются ошибкой.

По умолчанию (без `--preset`) не маскируются города, страны (`LOC`); даты (кроме именнованных наборов) - их можно включить через `--types`. Суммы денег не маскируются никогда.

## Установка

Python 3.10+:

```bash
git clone https://github.com/SuperB1aze/pii-mask-enhanced.git
cd pii-mask-enhanced
```
Windows (PowerShell):
```powershell
python -m venv venv
venv\Scripts\Activate.ps1
pip install -e ".[dev]"
```

Linux:
```bash
python3 -m venv venv
source venv/bin/activate
pip install -e ".[dev]"
```

Для `--audit` дополнительно нужна [Ollama](https://ollama.com) с моделью (дефолт `qwen3:1.7b`, переопределяется `PII_MASK_AUDITOR_MODEL`; адрес - `PII_MASK_OLLAMA_URL`, по умолчанию `http://127.0.0.1:11434`).

Для файлов `.doc` (Word 97-2003) нужен конвертер: LibreOffice или, на Windows, MS Word с `pywin32` (`pip install -e ".[word]"`). Путь к LibreOffice можно задать явно в `PII_MASK_SOFFICE` - на сервере это надежнее автопоиска.

## Деплой

На сервере (Linux) код работает из отдельного боевого каталога: незакоммиченные правки и переключение веток не должны менять поведение маскировщика, который в это время обрабатывает файлы.

```bash
./deploy.sh                               # боевой каталог по умолчанию: /data/apps/pii-mask
PII_MASK_HOME=/opt/pii-mask ./deploy.sh   # другой боевой каталог
```

Перед деплоем скрипт прогоняет тесты окружением `.venv` в каталоге репозитория (именно `.venv`, а не `venv`), поэтому на сервере его нужно создать один раз: `python3 -m venv .venv && .venv/bin/pip install -e ".[dev]"`. В бой ставится код последнего коммита - незакоммиченные правки не попадают.

## Использование

**CLI, пайплайн транскрипта:**

```bash
pii-mask mask встреча.md                  # -> встреча.masked.md + встреча.mapping.json
# встреча.masked.md уходит в облачную LLM, ответ сохраняем в summary.md
pii-mask unmask summary.md --mapping встреча.mapping.json -o summary.final.md
```

**Форматы на входе:**

| Вход | Результат |
|---|---|
| текст (`.md`, `.txt` и т.п., или `-` для stdin) | `.masked.md` |
| `.docx` | `.masked.docx` - оформление сохраняется |
| `.doc` | `.masked.docx` - через временную конвертацию в `.docx` (нужен конвертер, см. «Установка») |
| `.xlsx` | `.masked.xlsx` |
| `.pdf` | `.masked.md` - только текст, нужен `pdftotext` (poppler-utils); сканы без текстового слоя не поддерживаются |

Повторный `mask` следующего куска диалога с тем же `--mapping` продолжает нумерацию: одна сущность - одна метка на весь диалог.

**Флаги:** `--audit` (LLM-аудитор), `--no-ner` (только форматные), `--types PERSON,PHONE,...`, `--org-dict файл` (названия организаций списком).

**Именованные наборы.** Что считать персональными данными, описано в самом сервисе в виде наборов: вызывающему достаточно выбрать набор по имени или доверить выбор `auto`.

```bash
pii-mask presets                          # какие наборы есть и что в них
pii-mask mask резюме.pdf --preset resume      # мягко к организациям: работодатели без ООО
pii-mask mask счет.xlsx --preset accounting   # строго: торговые марки остаются в номенклатуре
pii-mask mask файл.md --preset auto           # выбрать по профилю документа
```

Список типов у наборов общий, различаются они строгостью к организациям. Флаг поверх набора может только добавить строгость (`--preset resume --ner-org-needs-form`); чтобы ослабить ее, нужно выбрать другой набор. `--types` поверх набора заменяет список типов целиком.

**Микросервис:**

```bash
pii-mask serve --port 8377    # слушает только 127.0.0.1
```

- `POST /mask` `{"text": "...", "mapping": null, "audit": false}` -> `{"masked_text": "...", "mapping": {...}}`; необязательные поля: `"ner": false` (без NER), `"types": ["PERSON", ...]`
- `POST /unmask` `{"text": "...", "mapping": {...}}` -> `{"text": "..."}`
- `GET /health/live` -> `{"status": "ok", "auditor": true|false}`

Тела запросов не логируются. По умолчанию постоянной службы нет: основной путь работы программы устроен через CLI, процесс поднимается на каждый вызов и потому всегда работает на актуальном коде. Если шлюз нужен постоянно, его запускают как user-службу systemd с именем `pii-mask`, указывающую в боевой каталог (`/data/apps/pii-mask`); `deploy.sh` перезапускает ее после обновления (см. «Деплой»).

## Гигиена mapping-файлов

`*.mapping.json` содержит оригиналы ПД. На Linux/macOS права 600 (только владелец) ставятся автоматически; на Windows это не работает - доступ к файлу ограничивают права на папку. Паттерн внесен в `.gitignore`. Файл живет рядом с задачей и удаляется вместе с ней.

## Тесты

Тесты проверяют, что шлюз не пропускает ПД и ничего не ломает:

- **распознаватели** - форматы и контрольные суммы (ИНН, СНИЛС, карта и т.д.), отсечение похожих номеров вроде артикулов;
- **маскировка и обратная подстановка** - одна сущность получает одну метку, mask -> unmask возвращает оригинал, повторный mask не создает второго слоя меток;
- **golden-тесты** (`tests/golden/`) - на вымышленных транскриптах и резюме ни одна строка с ПД не должна дожить до замаскированного текста;
- **форматы файлов** - .docx, .xlsx, .pdf, .doc: текст меняется, структура документа остается;
- **наборы, CLI и HTTP API**.

Запуск (нужны dev-зависимости `pip install -e ".[dev]"`):

```bash
python -m pytest -q        # в активированном venv
```

Часть тестов пропускается, если в системе нет нужной программы: PDF - без `pdftotext` (poppler-utils), конвертация .doc через Word - без MS Word и `pywin32`. Реальные ПД в тестах не используются.

## Официальные документы: акты, реестры, выгрузки

- **Извлечение текста из табличного PDF.** При извлечении текста необходимо использовать команду `pdftotext акт.pdf акт.txt` без флага `-layout`. В противном случае колоночный режим разносит ФИО, УИД и пары "реквизит - значение" по разным строкам, в связи с чем часть сущностей теряется.
- **ФИО прописными** (`ИВАНОВ ИВАН ИВАНОВИЧ`) ловятся правилами по суффиксу отчества без использования NER (по этой причине маскирование ФИО работает в том числе с флагом `--no-ner`). Одинокое отчество маскируется также.
- **ОГРН и УИД** маскируются по умолчанию, включая УИД, разорванный по дефису.

## Ограничения

- Вместо псевдонимов используются метки: в восстановленном тексте имя всегда в именительном падеже ("заявка для Иван Петров").
- NER может пропускать экзотические имена и транскрипционные искажения - для чувствительных текстов включайте `--audit`.
- **Названия организаций маскируются не все.** Название с организационно-правовой формой (`ООО "Ромашка"`, `Ромашка, ООО`) берется правилом, остальное - через NER, который может терять название рядом с датами и в колоночной верстке резюме. Название без единого формального признака (`Ромашка Россия`) правилами не берется. Такие случаи закрываются `--org-dict` или `--audit`.
- Агентные сценарии, где модель сама читает файлы, шлюз не покрывает.
- Номера поручений, реестров и входящих не маскируются. Их можно замаскировать отдельным набором правил под конкретный класс документов.
